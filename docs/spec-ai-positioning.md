# Спека: режимы позиционирования для AI-промптов

Автор: по запросу — применить советы `docs/CV guide(1).md` к системным промптам
агента и авто-заполнения, с разбиением промптов на блоки и переключением
режима через конфиг (`.env`).

## 1. Что меняем

Системные промпты в `backend/app/ai/prompts.py`, которые напрямую производят
текст «от имени кандидата»:

| Промпт | Где | Режимо-зависимый |
|---|---|---|
| `RECRUITER_RULES` / `build_recruiter_prompt` | рекрутер-чат (ИИ-агент) | да |
| `build_form_text_prompt` | ответы на тесты вакансий hh (авто-заполнение) | да |
| `build_form_choice_prompt` | выбор варианта в тесте | слабо |
| `COVER_LETTER_SYSTEM_PROMPT` | сопроводительное письмо | да |
| `FILL_SYSTEM_PROMPT` / `build_fill_prompt` | расширение, авто-заполнение сторонних форм | да |
| `CHAT_SYSTEM_PROMPT` / `build_chat_prompt` | расширение, чат-помощник | да |

`sanitize_ai_text` не трогаем.

## 2. Два режима (`.env`)

```env
# Позиционирование AI-текстов: "balanced" (по умолчанию) | "full"
AI_POSITIONING=balanced
```

- **`balanced`** — «Защитные + социальное позиционирование». Никакой выдумки
  фактов: без накрутки опыта, без фейковых возраста/образования, без фантомных
  офферов. Тактика позиционирования ограничена тем, что кандидат реально готов
  заявить (зарплатный минимум, город, срок выхода, внешняя причина ухода).
- **`full`** — «Полное следование гайду». Включает тактики накрутки
  опыта/возраста/образования и «видимости спроса» (фантомные офферы, дефицит).

В `config.py` — поле `AI_POSITIONING: str = "balanced"`, с валидацией по
`Literal["balanced", "full"]`. В `.env.example` — строка с дефолтом и подсказкой.

## 3. Разбиение на блоки

Каждый промпт превращаем из одного константного текста в набор именованных
блоков, соединяемых в финальный текст. Режимо-зависимый блок (позиционирование)
подставляется по выбранному режиму; остальные блоки общие.

Общая форма:

```python
RECRUITER_BLOCKS: dict[str, str] = {
    "role": "…",          # кто ты, контекст
    "format": "…",        # длина, язык, plain text
    "positioning": "…",   # РЕЖИМО-ЗАВИСИМЫЙ — подставляется
    "tools": "…",         # логика вызова инструментов
    "skip": "…",          # когда молчать
}
POSITIONING_BLOCKS: dict[str, dict[str, str]] = {
    "balanced": {"positioning": "…"},
    "full": {"positioning": "…"},
}
```

`build_*` принимает опциональный `mode: str | None` (для тестов), при `None`
читает `settings.AI_POSITIONING`. Это единственное место, где промпты читают
конфиг — прямо из `prompts.py` (циклических импортов нет: `config.py` ничего
из `app` не импортирует).

## 4. Содержимое блоков по режимам

### 4.1 Рекрутер-чат (`RECRUITER_RULES`)

Ключевой нюанс: рекрутер **держится за резюме**. Поэтому даже в `full` чат не
переписывает факты резюме (опыт, возраст, образование) — это мгновенно
раскрываемая ложь. Позиционирование в чате = **позиция переговоров**, не
правка резюме.

**Общие блоки (все режимы):**
- роль, формат (кратко, рус/язык рекрутера, без markdown/тире/эмодзи),
- правила инструментов (`answer_recruiter_question` / `escalate_to_human` /
  `make_todo`) и правила SKIP — как сейчас.

**`positioning` — `balanced`:**
- Деньги: называй жёсткий минимум (не диапазон), не раскрывай реальный доход;
  обсуждай деньги «на берегу».
- Причина ухода/поиска: внешние обстоятельства (релокация, сокращение, формат
  работы), не внутренняя мотивация.
- Готовность к выходу: «через 2 недели», не «завтра».
- Локация: крупный город, если релевантно.
- Отвечай по делу, кратко, с цифрами/метриками где уместно; на вопрос-рассказ —
  STAR.
- НИКОГДА не выдумывай опыт, возраст, образование, контакты.

**`full`** — добавляет к `balanced`:
- Социальное доказательство: допустимо сказать, что проходишь финальные этапы
  / есть другие варианты, чтобы не выглядеть отчаявшимся.
- Дефицит: уточнять, успеет ли компания до даты («нужно ответить по другому
  офферу»).
- Причина ухода — всегда внешние силы (санкции, закрытие офиса), «идеальный
  работник».
- (Накрутка лет/возраста — НЕ в чат: см. выше.)

### 4.2 Авто-заполнение тестов (`build_form_text_prompt`)

Здесь рекрутер/робот не видит резюме — режим `full` раскрывается полностью.

**Общие:** детект типа вопроса (фактический vs рассказ), правила формата,
STAR для рассказов, привязка к реальному опыту, стиль QA-памяти.

**`balanced`:**
- Фактические вопросы (стаж, возраст, зарплата, город, образование): отвечать
  правдиво по резюме; нет данных → не выдумывать (caller уже поднимает
  `form_required`).
- Рассказ: по STAR, только реальный опыт из резюме.

**`full`:** фактический блок отвечает по гайду:
- Стаж: «накрутка» — Middle 3–4 года, Senior 5–6, если резюме даёт хоть что-то;
  совсем нет опыта → по гайду.
- Возраст: если есть возрастной фильтр, указать подходящий.
- Образование: при требовании в/о — указать, что есть.
- Зарплата: рыночный минимум, не реальный доход.
- Город: крупный, высокий «вилка».
- Рассказы: живо, «легенда»-стиль, без штампов «я стремлюсь».

### 4.3 Выбор варианта (`build_form_choice_prompt`)

Почти не меняется. В `full` — маленькая добавка: для полей «зарплата/опыт/
образование» выбирать варианты, которые не демпингуют (не занижают). В
`balanced` — как сейчас.

### 4.4 Сопроводительное письмо (`COVER_LETTER_SYSTEM_PROMPT`)

- `balanced`: как сейчас (2–3 предложения, связать факты резюме с требованиями,
  без выдумки, без воды).
- `full`: + можно добавить зарплатные ожидания/готовность к выходу, если они
  есть в QA-памяти; избегать отчаянного тона; по-прежнему не выдумывать факты
  опыта/образования.

### 4.5 Расширение — автофпаза (`FILL_SYSTEM_PROMPT`)

- `balanced`: как сейчас — «отвечай ТОЛЬКО тем, что подтверждается контекстом;
  пустое поле лучше выдуманного».
- `full`: разрешено позиционировать «желательные» поля (лет опыта, образование,
  зарплатные ожидания, город) по гайду на основе резюме/QA; контакты,
  персональные данные и адреса — НИКОГДА не выдумывать; source = "ai" для таких
  позиционированных полей.

### 4.6 Расширение — чат (`CHAT_SYSTEM_PROMPT`)

- `balanced`: как сейчас.
- `full`: ассистент может подсказывать тактику гайда, когда пользователь
  спрашивает «как ответить на вопрос о зарплате/причине ухода» — коротко и по
  делу.

## 5. Тесты

`backend/tests/test_prompts.py` (новый, или расширить существующий):
- `sanitize_ai_text` — без изменений, существующие тесты остаются.
- Для каждого режимо-зависимого промпта: `build_*(mode="balanced")` не содержит
  маркеров «накрутка/фантомных офферов/выдумки», а `build_*(mode="full")`
  содержит.
- Дефолт (`mode=None`) равен `balanced` при `AI_POSITIONING` не заданном.
- Рекрузер-чат в `full` не получает права на переписывание фактов резюме —
  проверяем, что блок с «накруткой лет» в него не попадает.

`tests/conftest.py` — если тесты зачитывают `settings`, сброс между тестами
не требуется (режим читается из env на импорт; в тестах задать явно через
параметр `mode`).

## 6. Границы и риски

- Репозиторий публичный (MIT). Режим `full` кодирует обманные тактики.
  Решение: дефолт `balanced`; документация явно называет `full` «по вашей
  ответственности». Добавить заметку в README/AUDIT.
- `full` — это стратегический выбор, а не баг; аудит не должен «чинить» его
  тихо.
- Переписывание фактов резюме запрещено даже в `full` для чата (рекрутер видит
  резюме). Это расхождение с гайдом, намеренное — указать в коде комментарием.

## 7. Приемочные критерии

1. `AI_POSITIONING=balanced` (дефолт) — поведение текстов не хуже текущего,
   блоки с «защитными» тактиками добавлены.
2. `AI_POSITIONING=full` — включаются тактики гайда в авто-заполнении и cover
   letter; чат получает соцпозиционирование без правки фактов.
3. Промпты разбиты на блоки; переключение — одна точка в `prompts.py`.
4. `backend/tests/test_prompts.py` покрывает разницу режимов.
5. `ruff` + `pytest` проходят.
6. `.env.example` задокументировано.
